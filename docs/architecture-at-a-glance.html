1 · The boundary that defines the product

Most integration architectures draw the same boxes. What matters is where the line sits and what it guarantees: above it, everything is written for one client; below it, nothing changes between them. Each tenet on the right is drawn against the structure it produces, because a principle that is not visible in the diagram is not doing any work.

2 · The agentic foundation, and its limit

Every phase is the same loop, and the loop is what carries the guarantee rather than any phase's cleverness. An agent occupies exactly one station in it. The other three are code.

3 · Three clients, one core

The test of a pluggable architecture is not that it has interfaces. It is whether two engagements with nothing in common produce the same platform underneath.

4 · Tenets, and what each one forces

A tenet earns its place by ruling something out. These are stated with the structural consequence beside them, because that is the only way to tell an architecture principle from an aspiration.

TenetWhat it rules outStructural consequence
T1 Agents deciding anything Every gate is plain code. An agent that could approve its own output would make the audit trail decorative.
T2 Owning the execution Real work runs in the client's CI, where the code and credentials already are. The control plane never executes agent-authored code.
T3 A client redefining the ontology Node and edge types are fixed, or no phase logic is portable. Clients extend through namespaced types the platform stores but never reasons about.
T4 Coordinated identifiers A node's id is derived from what it is. Two components that never talk arrive at the same id, with no round trip — which is what lets the two planes assert about one criterion.
T5 Evidence as a later step Each phase asserts the edges it created at the moment its gate decides. There is no crawler, and the record cannot describe something that did not happen.
T6 A gate passing when it cannot check Fail closed. An empty graph, an unplaceable file path, an index that resolved four fifths of a codebase — each once passed silently in exactly the case it existed for.
T7 Migrating derived data The code graph is a function of a commit and is rebuilt, not migrated — which is why it is kept apart from the traceability graph, which is only ever appended to.
T8 Unmeasured controls Blast radius, coverage and capture rate are produced by harnesses with corpora and baselines. A control whose accuracy is unknown cannot carry the weight the design puts on it.
